What actually makes it feel polished
I think a few things contribute to the "it feels like a real app" quality:
The color system is coherent. There are only about 6 semantic color variables (textPrimary, textSecondary, textMuted, borderColor, cardBg, bg) and they're all derived from the same warm palette. Dark mode isn't just "invert everything" — each color was chosen to maintain the same visual hierarchy. The warm paper tone (#faf7f2 in light, #1a1816 in dark) gives it that Notion-like texture.
Theme color propagation is systematic. When you switch classes, a single themeColor variable changes, and because every accent usage references it — button backgrounds, filter borders, active states, Gantt bars, box shadows — the entire page transforms consistently. The transition: all 0.3s ease on key elements makes it feel like a smooth brand shift rather than a jarring repaint.
Restraint in motion. The animations are limited to a few specific moments: overlay fade-ins, sidebar slide-in, hover state transitions, and Gantt bar scale on hover. There are no entrance animations on page content, no bouncing loaders, no parallax effects. This matches the "clean, paper-like" aesthetic the design called for.
Typography does heavy lifting. The Source Serif 4 + DM Sans pairing creates clear hierarchy without needing heavy visual elements. Serif for titles and numbers, sans-serif for everything functional. The font weights are carefully stepped: 400 for body, 500 for secondary labels, 600 for active states, 700 for headings.
The information architecture is flat. There's essentially one top-level view state (which class am I in) plus a few modal/overlay states. The editor page replaces the content area rather than stacking on top of it. This keeps the mental model simple — you're always "in" one place, not navigating a deep tree.
What would change for production
For a real shipping product, I'd restructure significantly. The single-file approach breaks down past ~2000 lines. I'd likely move to a file-per-component structure with something like Vite + React Router for real page navigation, a proper state management solution (Zustand is lightweight enough), a real Markdown editor like Tiptap or Milkdown, and a design token system rather than inline color variables scattered everywhere. The inline styles would move to CSS modules or Tailwind — inline styles don't support media queries, pseudo-elements, or keyframes properly (I had to inject <style> tags as workarounds).
But for prototyping and iterating on UI/UX decisions — which is what we've been doing — the single-file approach has a real advantage: everything is visible, nothing is abstracted away, and changes are immediate.
