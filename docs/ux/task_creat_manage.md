## 旅途 4：发布与管理任务（管理员视角）

### 4.1 发布新任务

**触发**：进入班级页面后，若用户是该班级的 OWNER 或 ADMIN，顶部出现"发布任务"按钮（Primary）。


**页面布局**（上下两区域）：

**上方 — AI 解析区**：
- 一个大文本框（`textarea`，高度约 120px），placeholder "粘贴任务描述，AI 将自动提取关键信息..."
- "AI 解析"按钮（Secondary）
- 有一个提交附件的按钮，可以提交附件。（附件将属于该任务正文）用户点击结构化表单中的主按钮时，刚刚所写的内容和附件会被自动填写回正文编辑区。

现在这个流程在用户侧更加的明确了，点击创建任务按钮后，会有简易文本输入页面，可以上传附件，页面下方是任务基础信息表单。用户可以在输入文本表述和附件后，点击按钮（解析）来自动填入任务基础信息，确认无误后，点击（编辑正文）按钮跳转到 任务的编辑页面，在这个编辑页面中才有最终的发布任务按钮。
需要规范的问题是：用户输入文本表述和附件后，文件的储存形式是什么，由于存在附件，应该处理好minio相关的内容。解析过程需要发送两份内容，一份发给API要求“Structured model outputs”直接返回准确的json信息（注意返回的时间应该包含时区或默认是用户时区，在发送给ai的prompt中应该包含用户设置的时区和当前用户时区的本地时间（含星期几），此处细节很重要，因为用户可能会输入诸如后天上午，本周日晚上这样的表达。）。发送给AI的内容要随带附件（后端已经设计相关流程，目前仅支持pdf和图片类型文件），以考虑附件中存在任务相关信息。同样的一份内容再使用另一个prompt发送给AI要求其返回md格式的梳理任务的文档，应该以某种形式暂存，客户端进入编辑正文页面时会拉取并填回编辑区，原本上传的附件也会被移动到编辑区，当用户发布任务的时候，才正式发布任务。

要求按送给AI的数据清单：
- 用户输入的文本表述
- 用户上传的附件文件名
- 用户上传的图片或pdf附件
- prompt中需要包含用户时区和当前用户时区的本地时间（含星期几），要求生成的标题使用用户相同语言（prompt使用英文）
- 结构化返回的要求：
```json
{
  "title": "任务标题，必填",
  [{
  "start_time": "ISO 8601格式的日期时间字符串，选填",
  "end_time": "ISO 8601格式的日期时间字符串，必填",},{},{}
  ]
  "allow_late_submission": true, // 是否允许延迟提交，布尔值，选填，默认true
}
```
start end time包含时区信息。其次，这是一个数组（不超过3种可能数据），意味着更如果AI拿不准用户意图，应该返回多个可能的时间段。并在解析返回时，又前端再次弹窗询问用户你想使用那个时间段？n选一或者选都不是来手动输入。应该提示AI尽可能不要使用列表时间返回，仅在必要时。

对于另一个prompt返回的md格式的梳理任务的文档，需要特别提示在生成时遵循用户输入的内容，不可以添油加醋生成一些用户没有提到的内容，并且使用和用户相同的语言。

**下方 — 结构化表单**：
- 任务名称（必填）
- 开始时间（日期时间选择器，选填，如果不填写则表示现在开始，当然也给用户提供一个“立即”按钮）
- 截止时间（日期时间选择器，必填）
- 是否允许延迟提交（Toggle，默认开启；当前版本 v1 仅存储，不实际限制）
- 前置任务（多选，从当前班级已有任务中选择，选填）
- "编辑正文"按钮（Primary）--跳转到edit

**AI 解析交互**：
1. 用户在上方文本框输入内容，点击"AI 解析"
2. 按钮变为 loading 状态，文字"解析中..."
3. 解析完成：
   - 成功识别的字段自动填入下方表单（带高亮动画，如淡黄色背景 → 正常背景的过渡，持续 1 秒）
   - 未识别的字段保持为空
   - Toast 提示"已解析，请检查并确认"
4. 解析失败（网络或 LLM 错误）：Toast 错误提示"解析失败，请手动填写"，不影响表单

**验证规则**：
- 截止时间必填，且必须是有效的未来时间（在前端实时校验）
- 若截止时间早于开始时间，截止时间字段显示错误："截止时间不能早于开始时间"
- 点击发布时，名称和截止时间若为空，对应字段显示红色 error 样式

**语音输入（流式转录）**：
- 底部工具栏中附件按钮旁增加「Record」按钮（麦克风图标）
- 点击开始：通过 AssemblyAI 流式 WebSocket 实时转录语音为文字，文字实时追加到 textarea
- 按钮变为红色脉动圆点 + "Stop"，请求麦克风权限
- 再次点击停止：结束流式连接，文字已写入输入区
- 技术方案：前端获取 POST /stt/token 临时 Token → WebSocket 连接 AssemblyAI → PCM16 音频流 → 实时转录

**AI 解析按钮显示时机**：
- 只要用户有任何输入（文字 OR 附件），即显示 AI 解析按钮
- 点击解析时：直接使用 textarea 中的文字走正常解析流程（语音已实时转为文字）

### 4.2 编辑任务

富文本编辑器。如果是从创建任务过来的，正文和附件应该均已填入。
按钮将会是 发布任务 或 保存修改，取决于用户是从哪里进入的编辑页。

**AI Rewrite（AI 重写）**：
- 编辑页 header 右侧增加「AI Rewrite」按钮（Sparkles 图标）
- 点击打开弹窗（Dialog），包含：
  - 文本输入框：用户输入修改指令（placeholder: "Describe the changes you want..."）
  - 语音输入按钮：使用流式转录实时将语音写入文本框
  - 提交按钮：将当前正文 + 修改指令发送给 AI（POST /tasks/{taskId}/revise）
- AI 返回修改后的正文，写回编辑区，Toast 提示 "Content revised by AI"
- 修改前的内容保存到撤销栈

**撤销功能**：
- 编辑页 header 显示「Undo」按钮（仅在撤销栈非空时显示）
- 点击恢复到上一版本内容
- 基于浏览器内存的简单撤销栈，每次 AI 修改前 push 当前内容

**延期功能**：
- 编辑页 header 显示「Extend Deadline」按钮（仅在 publish 模式且任务有截止时间时显示）
- 点击弹出对话框：
  - 显示当前截止时间
  - 预设选项：+1 小时、+3 小时、+1 天、+3 天
  - 自定义输入：数字 + 单位（小时/天）
  - 显示新截止时间预览
  - 确认/取消按钮
- 仅允许延长（新时间必须晚于当前截止时间），前端校验
- 确认后调用 updateTask API 更新 dueAt

### 4.3 查看任务（管理员视角）

**页面**：与成员视角（expand_task.md）相同 URL，但内容不同

**管理员额外看到**：
- 任务详情顶部增加统计区：三个数字 —— 班级成员数 / 已读人数 / 已提交人数
  - 格式：`12 人 · 8 已读 · 5 已提交`
- 正文下方不显示"我的提交"区域，显示"查看所有提交"入口（次级链接或 Secondary 按钮）
- 右上角有"编辑任务"和"删除任务"操作（Ghost 按钮）

### 4.4 删除任务

删除按钮应该只在 **任务没有任何提交记录** 时显示。点击后弹出确认框："确定要删除这个任务吗？此操作不可恢复。" 确认后执行删除操作，成功后返回任务列表并显示 Toast 提示"任务已删除"。
