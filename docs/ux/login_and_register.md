## 登录与注册旅程

### 注册第一步

**入口**：未登录用户访问系统后进入 `/login`，点击“没有账号？注册”。

**页面**：`/register`

**用户看到**：

- 一个居中的卡片
- 注册关闭时，只显示“注册功能当前未开放”提示，不显示表单
- 第一步只输入邮箱
- “已有账号？登录”跳转链接

**交互**：

- 提交邮箱后，系统发送验证邮件
- 若邮箱已注册，直接提示失败
- 24 小时内同一邮箱最多发送 5 封注册邮件

### 注册第二步

**页面**：`/register/complete?token=...`

前端先调用 `GET /auth/verify-token?purpose=REGISTRATION`，只有 token 有效时才显示表单。

**表单字段**：

1. 邮箱，只读，来自已验证 token
2. 密码，至少 8 位
3. 昵称，可选
4. 学校，可选
5. 学号，选择学校后变为必填
6. `trustDevice` 复选框，用于“记住此设备 30 天”
7. 用户协议 / 隐私政策勾选项

**成功结果**：

- 自动进入已登录状态
- 跳转到 `/dashboard`
- 自动创建私人班级

### 登录页

**页面**：`/login`

**用户看到**：

- 邮箱
- 密码
- “记住此设备 30 天”复选框
- “忘记密码？”链接
- “没有账号？注册”链接

**行为**：

- 未勾选 `trustDevice`：7 天固定过期 session
- 勾选 `trustDevice`：30 天滑动续期 session

### 忘记密码

1. 用户在登录页进入忘记密码流程并提交邮箱。
2. 系统总是提示“如果该邮箱存在，已发送重置链接”，避免泄露账号是否存在。
3. 用户点击邮件链接进入 `/reset-password?token=...`。
4. 前端先调用 `GET /auth/verify-token?purpose=PASSWORD_RESET`。
5. 用户填写新密码并提交，或点击“暂不重设，直接登入”。

**成功结果**：

- 重置密码：提示密码重置成功，自动登录并进入站点；旧浏览器 sessions 会被注销。
- 暂不重设：不修改密码，自动登录并进入站点；原有 sessions 保持可用。
