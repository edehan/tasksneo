# Internationalization (i18n) Guide

TaskFlow uses [next-intl](https://next-intl.dev/) for frontend internationalization.

**English (`en.json`) is the source of truth.** All other locale files are community-maintained translations. Contributors are responsible for keeping their locale in sync with the English source.

## File locations

```
apps/web/src/i18n/
├── locale.ts          # Supported locales, matching logic
├── messages.ts        # Dynamic message loader
├── request.ts         # Server-side locale resolution
└── messages/
    ├── en.json        # English (source — maintained by core team)
    ├── zh-CN.json     # Simplified Chinese
    ├── fr.json        # French
    └── ja.json        # Japanese
```

## Updating an existing locale

1. Compare your locale file against `en.json` to find missing or outdated keys:
   ```bash
   # Quick diff of top-level keys
   diff <(jq -S 'keys' apps/web/src/i18n/messages/en.json) \
        <(jq -S 'keys' apps/web/src/i18n/messages/zh-CN.json)
   ```

2. Add any missing keys with the appropriate translation. Keep the same JSON structure and key order as `en.json`.

3. Interpolation parameters (e.g. `{name}`, `{count}`) must be preserved exactly as they appear in English.

4. Build to verify:
   ```bash
   pnpm --filter web build
   ```

## Adding a new locale

1. **Copy the English source:**
   ```bash
   cp apps/web/src/i18n/messages/en.json apps/web/src/i18n/messages/ko.json
   ```

2. **Translate all values** in the new file. Do not change any keys.

3. **Register the locale** in `apps/web/src/i18n/locale.ts`:
   ```typescript
   // Add to the array
   export const SUPPORTED_LOCALES = ["en", "zh-CN", "fr", "ja", "ko"] as const;

   // Add fuzzy matching rule in matchLocaleTag()
   if (normalized.startsWith("ko")) return "ko";
   ```

4. **Add the import** in `apps/web/src/i18n/messages.ts`:
   ```typescript
   case "ko":
     return (await import("@/i18n/messages/ko.json")).default;
   ```

5. **Add the language label** to the `appSidebar` section in every existing locale file (including your new one), so the language name shows in the locale switcher:
   ```json
   "langKo": "한국어"
   ```
   Update the type union in `app-sidebar.tsx` if needed.

6. **Build and test:**
   ```bash
   pnpm --filter web build
   ```
   Switch to your locale via the user avatar dropdown to verify rendering.

## Conventions

- Key names are `camelCase`, grouped by page or component (e.g. `settingsProfile`, `appSidebar`).
- Keep translations concise — UI space is limited, especially in buttons and labels.
- Do not add keys that don't exist in `en.json`.
- If you find a missing English key, open an issue or add it to `en.json` first.
